# نجاح (Nagah) — منصة ربط المدرسين الخصوصيين بأولياء الأمور

منصة MVP مبنية بـ Node.js/Express تربط أولياء الأمور بالمدرسين الخصوصيين، مع لوحة إدارة للموافقة على تسجيل المدرسين الجدد.

## المميزات

- بحث في المدرسين المعتمدين (بالمادة/المرحلة/المنطقة)
- تسجيل مدرس جديد (يدخل في حالة "قيد المراجعة" لحد ما الإدارة توافق)
- تسجيل ولي أمر (3 حقول) — بعد التسجيل يظهر رقم تواصل المدرس
- تقييمات ومراجعات للمدرسين
- مفضلة وحجوزات لكل ولي أمر
- لوحة إدارة (`/admin.html`) لقبول/رفض طلبات تسجيل المدرسين

## التقنية

- **Backend:** Node.js + Express
- **التخزين:** ملف JSON محلي (`data.json`) — مناسب لمرحلة الـ MVP فقط، مش قاعدة بيانات حقيقية
- **Frontend:** HTML/CSS/JS عادي بدون build step، بيتقدّم كملفات static من `/public`

## التشغيل محليًا

```bash
npm install
cp .env.example .env   # عدّل ADMIN_KEY لو حابب
npm start
```

الموقع هيشتغل على `http://localhost:3000` (أو المنفذ اللي في `PORT`).

- الصفحة الرئيسية: `/`
- لوحة الإدارة: `/admin.html` (تحتاج الـ Admin Key اللي في `ADMIN_KEY`)

## متغيرات البيئة

| المتغير | الوصف | افتراضي |
|---|---|---|
| `PORT` | المنفذ اللي السيرفر بيشتغل عليه | `3000` |
| `ADMIN_KEY` | المفتاح المطلوب في هيدر `x-admin-key` عشان تدخل على `/api/admin/*` | `admin123` |
| `DATA_PATH` | مسار ملف تخزين البيانات | `./data.json` |

**مهم:** غيّر `ADMIN_KEY` لقيمة قوية وعشوائية قبل أي نشر فعلي — القيمة الافتراضية مكشوفة في الكود.

## ⚠️ ملاحظة مهمة عن التخزين والنشر

البيانات متخزنة في ملف `data.json` على القرص المحلي للسيرفر. أغلب منصات الاستضافة (Railway, Render, Heroku..) بتستخدم **filesystem مؤقت** بيتصفر مع كل إعادة نشر أو إعادة تشغيل، يعني البيانات (المدرسين، الحجوزات، التقييمات) ممكن تتمسح.

عشان تحافظ على البيانات بعد النشر، لازم واحد من اتنين:
1. تربط **Volume دائم** (Persistent Volume) على المنصة وتوجّه `DATA_PATH` عليه، أو
2. تنتقل لقاعدة بيانات حقيقية (Postgres/SQLite على volume/MongoDB) — الأفضل على المدى المتوسط لأي حمل استخدام حقيقي.

## API Endpoints

| Method | Path | الوصف |
|---|---|---|
| GET | `/health` | فحص حالة السيرفر |
| GET | `/api/tutors?q=` | بحث في المدرسين المعتمدين |
| GET | `/api/tutors/:id` | تفاصيل مدرس (رقم الهاتف يظهر فقط لو `parent_id` صحيح) |
| POST | `/api/tutors` | تسجيل مدرس جديد (حالة "قيد المراجعة") |
| POST | `/api/tutors/:id/reviews` | إضافة تقييم |
| POST | `/api/parents` | تسجيل ولي أمر |
| POST/DELETE | `/api/parents/:pid/favorites/:tid` | إضافة/إزالة من المفضلة |
| GET | `/api/parents/:pid/favorites` | قائمة المفضلة |
| POST | `/api/bookings` | طلب حجز حصة |
| GET | `/api/parents/:pid/bookings` | حجوزات ولي الأمر |
| GET | `/api/admin/tutors?status=` | (Admin) قائمة المدرسين حسب الحالة |
| POST | `/api/admin/tutors/:id/approve` | (Admin) قبول مدرس |
| POST | `/api/admin/tutors/:id/reject` | (Admin) رفض مدرس |

## النشر

المشروع جاهز للنشر على أي منصة بتدعم Node.js (Railway, Render, Fly.io..):

1. تأكد إن `npm start` هو أمر التشغيل
2. اضبط متغيرات البيئة (`ADMIN_KEY` خصوصًا)
3. اربط Volume دائم لو عايز تحافظ على البيانات (راجع القسم اللي فوق)

## قيود معروفة (خطوات تالية مقترحة)

- مفيش تسجيل دخول حقيقي بباسورد لأولياء الأمور أو المدرسين — أي حد يعرف الاسم/الهاتف يقدر "يسجل" بسهولة
- المدرس نفسه مالوش لوحة تحكم يشوف فيها طلبات الحجز أو يعدّل بياناته
- التخزين ملف JSON مش قاعدة بيانات حقيقية — محتاج ترقية لأي استخدام فعلي
- مفيش رفع صور/إثباتات هوية للمدرسين
